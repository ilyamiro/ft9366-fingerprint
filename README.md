# ft9366-fingerprint

Open-source fingerprint driver for the **FocalTech FT9366** reader (USB `2808:a658`, behind a Realtek
RTS5811 bridge), as found in several laptops. Works with `fprintd`, so you get `fprintd-enroll`,
`fprintd-verify`, and fingerprint login/`sudo`. Packaged for **NixOS**.

## Install (NixOS with flakes)
```nix
# flake.nix
inputs.ft9366.url = "github:ilyamiro/ft9366-fingerprint";

# in your nixosSystem modules:
ft9366.nixosModules.default
```

## Install (NixOS without flakes)
```nix
# configuration.nix
imports = [ /path/to/ft9366-fingerprint/driver/nixos-ft9366.nix ];
```

Then:
```
sudo nixos-rebuild switch
fprintd-enroll      # press the same finger 12 times, a bit differently each time
fprintd-verify
```
Optional login / sudo: `security.pam.services.sudo.fprintAuth = true;`
(keep your password as a fallback).

## What to expect
The sensor is tiny (3x4 mm). On the author's fingers roughly half to two thirds of genuine touches
match on the first try, and other fingers were rejected in every test. Press flat and firmly, cover the
whole sensor, and retry on a miss. Thresholds were tuned on one person's fingers; please report how it
works for you. See [docs/HOW_IT_WORKS.md](docs/HOW_IT_WORKS.md).

## Try it without installing
```
cd driver && nix-build -E 'with import <nixpkgs> {}; callPackage ./libfprint-ft9366.nix {}' -o result
cd ../test && ./build_test.sh && ./run_driver_test.sh 8   # stop fprintd first
```

## Repository layout
```
libfprint/drivers/ft9366/   the driver (same layout as libfprint's tree): USB code, matcher, command tables
patches/                    changes to libfprint's own files (meson, hwdb) = what an upstream MR would contain
driver/                     Nix packaging (libfprint with the driver applied) and the NixOS module
tools/                      generators for the command tables / descriptor pattern, offline matcher evaluation
docs/                       how it works, USB protocol, draft upstream issue
```

## About this implementation
This is an independent implementation in the sense that all code is my own. The USB protocol was learned from
captures of the vendor driver's traffic, and the vendor driver was also examined with static analysis to
understand its structure, so the matcher's overall approach (binary-descriptor keypoints, rigid consensus,
ridge-map overlay) follows the vendor's design using publicly known techniques. It contains no vendor source
code, binaries, tables or trained data; the descriptor sampling pattern is generated by `tools/gen_pairs.py`.
The accept thresholds come from my own measurements (one of them coincides with a value in the vendor library).
It is not affiliated with or endorsed by FocalTech or Realtek. See `docs/UPSTREAM_ISSUE.md` for the full statement.
